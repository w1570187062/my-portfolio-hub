# 复盘页改版方案

> **根因一句话**：复盘页是三次独立迭代叠在一起的产物，每个迭代只管"我这块卡"的呈现，**KPI 年化（全持有期加权）、基准对比收益（近 1 年 pnl_daily）、业绩榜年化（逐品独立持有期）三者时间窗口和数据源完全不联动**，用户扫一眼像三个独立 app 并排。
>
> **推荐方案**：方案 C「叙事化 · 结论卡 + 可下钻」的简化版 —— 首屏给一句话诊断结论，下方按「归因分解 → 逐品明细 → 基准对比」顺序组织，时间区间全局联动。

---

## 一、割裂现状：具体证据

### 1.1 当前页面分区（从上到下）

| 序号 | 区块 | 来源 | 时间窗口 | 核心指标 |
|---|---|---|---|---|
| ① | KPI 4 卡 | `/api/review` | **无**（年化由逐品独立持有期 XIRR 算出，加权成组合） | 组合实测年化、收益合计(浮盈+落袋)、累计落袋、整体胜率 |
| ② | 基准对比卡 | `/api/review/benchmark` | **近 1 年**（pnl_daily 不足时自动收缩） | 组合区间收益 vs 沪深300/标普500/纳指100 |
| ③ | 业绩表现卡 | `/api/review.perf` | **无统一**（每品独立持有期） | 逐品年化 + 逐品收益金额 |

### 1.2 割裂点清单

#### 割裂 1：数据源不一致导致同一"组合"在两处算出不同结果

- **基准对比卡**（`benchmark.go L71`）明确注释："不含理财与现金"，只用 `pnl_daily` + 持仓每日盈亏
- **KPI 组合年化**（`review.go L469-501`）含持仓 + 理财 + 现金（现金按 0 计入）
- 用户看到 "KPI 年化 8.5%" 紧接着 "基准对比近 1 年 -2.3%"，不知道哪个对应哪个。基准对比实际上比 KPI 少算了理财，但**这一点前端完全没提示**。

#### 割裂 2：时间窗口完全不联动

| 区块 | 时间窗口 |
|---|---|
| 组合年化 | 逐标的独立持有期（有的 3 年，有的 20 天），加权后失去"哪个时间段"的语义 |
| 基准对比 | 固定近 1 年（账本短就收缩，但前端只改标题文字，没改指标含义） |
| 业绩榜逐品年化 | 每品自己的独立持有期 |

三者并排展示，但说的根本不是同一个时间段。

#### 割裂 3：年化 vs 持有期收益率口径冲突

- **业绩榜的百分比列**是 **年化（XIRR）**
- **投资页同一标的的收益率**是 **持有期收益率**（(现价-成本)/成本）
- 靠一行小字说明（`index.html L481`），但用户很容易搞混"这个 25% 到底是年化还是总共赚了 25%"

#### 割裂 4：KPI "整体胜率" 语义模糊

`app.js L13604-13611` 前端算的：全 perf 里 gain_cny > 0 的占比。但分母同时包含：
- 持仓中标的（市值在波动，明天可能翻绿）
- 已平仓标的（已落袋，定数）

"整体胜率 60%"到底指什么？是"历史上 60% 决策是对的"还是"现在 60% 持仓在赚钱"？

#### 割裂 5：后端白算的数据前端完全没展示

| 后端字段 | 位置 | 含义 | 前端状态 |
|---|---|---|---|
| `reviewResp.idle` | `review.go L156, L503-514` | 闲置现金金额、占比、每年少赚 | **已删**（v6.2 删掉闲置现金卡） |
| `reviewResp.targets` | `review.go L152, L176-180` | 各类别目标年化 | **未用** |
| `reviewResp.goal_pct` / `goal_fallback` / `gap_pp` / `gap_amt` | `review.go L146-151, L536-548` | 整体目标年化、差距、每年少赚 | **未用** |
| `reviewItem.target` | `review.go L107` | 每品类目标年化 | **未用** |

相当于后端已经算好了"目标年化 7%，差距 1.5pp，每年少赚 ¥5,000"，前端直接扔了。

#### 割裂 6：视觉层级打架

- KPI 四张卡并排，"组合实测年化 %"和"收益合计 ¥"字号一样大，但维度完全不同
- 基准对比卡和业绩表现卡视觉权重相同，但基准对比是辅助信息、业绩表现是主体
- 圆环按 `|收益|` 绝对值汇总，盈利+1000 和亏损-1000 占比一样，表达的是"波动集中在哪类"而不是"资产配置在哪类"，但中心又显示正数或负数的"收益合计"

## 二、可用数据盘点

### 2.1 已有接口/字段

| 数据 | 接口/表 | 字段 | 可用 |
|---|---|---|---|
| 持仓+已平仓+理财逐品明细 | `GET /api/review` → `perf[]` | name, symbol, state, key, mv_cny, invested_cny, gain_cny, ann, target, days, quality, note | ✅ 全 |
| 组合实测年化（XIRR 市值加权） | `GET /api/review` | `ann`, `ann_est` | ✅ |
| 组合目标年化 | `GET /api/review` | `goal_pct`, `goal_fallback`, `gap_pp`, `gap_amt` | ✅ 已有但未展示 |
| 各类别目标年化 | `GET /api/review` | `targets[]` (stock/fund/wealth/cash) | ✅ 已有但未展示 |
| 闲置现金 | `GET /api/review` → `idle` | amount, weight, cost_cny, items[] | ✅ 已有但前端删了 |
| 每日盈亏快照 | `pnl_daily` | date, total_cny, base_cny, contrib_cny | ✅ 全历史 |
| 持仓每日盈亏分解 | `/api/pnl/history` | 每品每日盈亏 | ✅ |
| 基准指数区间收益 | `GET /api/review/benchmark` | portfolio.ret_pct, bench[].ret_pct, bench[].excess_pp | ✅ 近 1 年 |
| 交易流水 | `position_tx` | BUY/SELL/DIV，每笔日期、金额、费用、已实现盈亏 | ✅ |
| 理财快照 | `wealth_snapshot` | 每日 amount, cashflow, dividend | ✅ |
| 现金流（内部划转） | `cash_flow` | 子账户间划转 | ✅ |
| 汇率 | `market.FetchFXRates()` | CNY/HKD/USD | ✅ 实时 |

### 2.2 算得出来但当前没算的指标（纯前端能做）

| 指标 | 数据源 | 做法 |
|---|---|---|
| **逐品持有期收益率**（不同于年化） | `perf[].gain_cny` + `perf[].invested_cny`（持仓中用 mv_gain？需要前端从 position_tx 汇总本金） | 前端从 perf 逐品反推或后端补字段 |
| **逐品超额收益**（品实测年化 − 品目标年化） | `perf[].ann` − `perf[].target` | 直接算 |
| **每日净值曲线**（含组合、持仓、理财、基准） | `pnl_daily` + 指数行情 | 后端按区间聚合后返回 |
| **收益归因分解**（选品收益 + 资产配置收益 + 择时收益） | 需要每日持仓明细 vs 每日目标配置 | 后端算（需要每日目标配置快照或按目标比例 × 实际市值） |
| **区间切换**（近 1 月 / 3 月 / 6 月 / 1 年 / 全部） | `pnl_daily` 全历史 + 基准指数多窗口 | 前端按已有数据切片 |

### 2.3 需要后端补的数据

| 缺口 | 原因 | 工作量 |
|---|---|---|
| **基准对比与 KPI 的数据源对齐** | 当前 benchmark 只用 pnl_daily（不含理财），KPI 含理财；要么让 benchmark 也算上理财，要么 KPI 拆成"持仓年化"和"含理财年化"两个数 | 小（`benchmark.go` 补理财每日盈亏） |
| **已平仓逐品持有期收益率** | reviewItem 已有 invested_cny（本金），只需补 `holding_return = gain_cny / invested_cny` | 极小（后端 review.go 加一个字段） |
| **每日净值 + 基准曲线的时间序列** | 当前只有 pnl_daily（组合每日盈亏），没返回每日累计净值 vs 指数的序列 | 小（后端按区间聚合，加一个 `/api/review/nav?range=1y` 接口） |

## 三、竞品做法提炼

### 3.1 Ghostfolio（开源投资组合追踪）

| 做法 | 适用 | 不适用 |
|---|---|---|
| 首屏 **"Today" + "YTD" + "1 Year" + "All Time"** 全局时间切换，所有区块联动 | ✅ 解决"时间窗口不联动"的核心问题 | 切换需要后端多算几个区间，有性能成本 |
| 左侧 **"Holdings" 明细表**，中间 **分布图/饼图**，右侧 **Summary KPI** 三栏布局 | ✅ 信息密度高，但适合宽屏 | 移动端需要折叠，当前项目移动端资源有限 |
| **"Performance" 独立标签页**：净值曲线（组合 vs 基准） + 收益归因（按类别/标的） | ✅ 归因在前、明细在后的叙事 | 当前项目还没到"归因分解"这一步，可以后做 |

### 3.2 Portfolio Performance（开源桌面）

| 做法 | 适用 | 不适用 |
|---|---|---|
| **"Securities" 总览表**：每只标的的"总成本 / 当前市值 / 收益率 / 年化 / 波动率 / 夏普" | ✅ 表格信息密度高，但当前项目已有业绩榜，只需补持有期收益率列 | 波动率、夏普需要更长历史数据，当前可能不够 |
| **"Chart of the day"**：每日盈亏热力图 + 净值曲线并排 | ✅ 盈亏日历已在首页有了，复盘页可以复用 | 重复感，复盘页应该给的是"诊断"而不是"展示" |
| **IRR vs MWR vs TWR 三种收益率并存** | 当前项目只有 XIRR（时间加权近似），如果引入 TWR 需要每日净值序列 | 认知成本高，用户分不清 IRR 和 TWR |

### 3.3 Sharesight（海外付费）

| 做法 | 适用 | 不适用 |
|---|---|---|
| **"Annualised return" 大字 + "Total return (holding period)" 小字并排** | ✅ 完美解决"年化 vs 持有期"的口径混淆 | 需要后端同时返回两个数字 |
| **"Top winners / Top losers" 双榜单** | ✅ 把赚最多和亏最多分开，一目了然 | 当前单一榜按总额排序，亏的在最下，其实差不多 |
| **"Contribution & withdrawals" 资金进出时间轴** | ✅ 复盘"择时"决策 | 当前项目只有现金流，没有"择时好坏"的评估逻辑 |

### 3.4 雪球 / 同花顺

| 做法 | 适用 | 不适用 |
|---|---|---|
| **"收益率战胜 xx% 的用户"** 排名 | 用户有攀比心理，但需要平台数据，当前是个人产品 | ❌ 不需要 |
| **"收益归因" 饼图**（行业贡献、个股贡献） | ✅ 类似 Ghostfolio | 当前分类太粗（股票/基金/理财/现金），归因意义有限 |

### 3.5 Morningstar（机构风格）

| 做法 | 适用 | 不适用 |
|---|---|---|
| **5 张风险调整指标卡**：Alpha / Beta / Sharpe / Treynor / R² | ✅ 专业用户看组合质量 | 普通用户看不懂，且当前历史数据可能不够算 |
| **"Style box" 九宫格**（大盘/中盘/小盘 × 价值/混合/成长） | 展示风格暴露 | 当前分类维度不够细 |
| **基准指数下拉切换** | ✅ 当前固定三个基准，可以让用户选 | 当前三个指数已覆盖主要市场 |

### 3.6 通用模式总结

| 模式 | 价值 |
|---|---|
| ① **归因在前，明细在后** —— 先告诉用户"为什么好/坏"，再给"每只怎么样" | 解决"看完不知道该做什么"的问题 |
| ② **时间区间全局联动** —— 一个切换器控制所有区块的时间窗口 | 解决"同一页三个时间口径"的割裂 |
| ③ **年化 vs 持有期收益率并列展示** —— 大字年化、小字持有期，口径写死 | 解决"年化 vs 总收益"的混淆 |
| ④ **超额收益单列** —— 跑赢/跑输基准多少 pp，而不是只给组合绝对值 | 解决"8% 到底算好还是差"的问题 |
| ⑤ **首屏一句话结论卡** —— "你的组合近 1 年跑赢沪深300 5.2pp，但持有集中在 XX 类" | 解决"看完没结论"的问题 |
| ⑥ **基准切换器** —— 让用户选主要市场基准（沪深300/标普500/纳指100/比特币） | 海外持仓的用户对标普 500 更关心 |

## 四、三个改版方案对比

### 方案 A：轻改 · 重排 + 统一口径（1-2 天，几乎纯前端）

**核心思路**：不动后端数据源，只解决"割裂"的 6 个具体问题，不新增功能。

#### 信息架构（从上到下）

```
┌─────────────────────────────────────────────────────┐
│ KPI Section（重排 + 去歧义）                        │
│   左：组合年化（含理财） / 中：年化差距 / 右：闲置现金│
│   删掉"整体胜率"（语义模糊），改展示"跑赢指数"      │
├─────────────────────────────────────────────────────┤
│ 基准对比卡（保留，但顶部加全局时间区间切换器）        │
│   组合 vs 沪深300 / 标普500 / 纳指100              │
│   统一口径：基准卡标注"仅持仓"，KPI 标注"含理财"    │
├─────────────────────────────────────────────────────┤
│ 业绩表现卡（重排）                                   │
│   左：圆环（保持）                                  │
│   右：列表 —— 补"持有期收益率"列（从小写字，年化并列）│
│        每行标"超额" = 实测年化 − 目标年化           │
└─────────────────────────────────────────────────────┘
```

#### 解决的割裂问题

| 割裂 | 处理 |
|---|---|
| 数据源不一致 | KPI 和基准对比各标清楚口径 |
| 时间窗口不联动 | 基准卡顶部加区间切换器（近3月/6月/1年/全部），驱动 pnl_daily 切片 |
| 年化 vs 持有期 | 列表同时展示两个 |
| 胜率模糊 | 删掉，改成"跑赢基准 N pp" |
| 后端白算数据 | 把 idle（闲置现金）和 gap_pp 展示出来 |
| 视觉层级 | 删掉"整体胜率"让 KPI 更聚焦 |

#### 需要的数据

纯前端可完成。逐品持有期收益率 = gain_cny / invested_cny（持仓中 fallback 用 gain_cny / 原始本金，但原始本金需要从 position_tx 反推或换用 mv_cny - gain_cny 反推）。

#### 风险

- 前端用 mv_cny - gain_cny 反推持仓中标的本金可能有精度问题（分红、拆股会影响）
- 基准卡的时间切换只影响基准卡自身，不影响 KPI 和业绩榜（后两者还是"全持有期"口径），割裂没完全解决

---

### 方案 B：重构 · 收益归因驱动（3-5 天，前端为主 + 少量后端）

**核心思路**：把"逐品诊断"升级为"组合级归因"，从"整体好/坏"→"为什么好/坏"→"哪只拖了后腿"的顺序组织。

#### 信息架构（从上到下）

```
┌─────────────────────────────────────────────────────┐
│ ① 全局区间切换器                                    │
│   [近 1 月] [近 3 月] [近 6 月] [近 1 年] [全部]   │
│   所有区块联动                                      │
├─────────────────────────────────────────────────────┤
│ ② 组合绩效摘要卡（新增 "跑赢/跑输" 为核心指标）      │
│   「近 1 年：+8.5%」 大字                          │
│   「跑赢沪深300 5.2pp / 跑输标普500 3.1pp」        │
│   小字：年化 XIRR / 持有期收益率 / 最大回撤         │
├─────────────────────────────────────────────────────┤
│ ③ 归因分解（新增）                                  │
│   左侧：选品贡献饼图（各品类 alpha 之和）           │
│   右侧：资产配置贡献（目标配置 vs 实际配置的年化差） │
│   下方："谁拖了后腿" Top 3 拖累品                   │
├─────────────────────────────────────────────────────┤
│ ④ 基准对比（保留，精简为 3 列 + 组合对比条）        │
├─────────────────────────────────────────────────────┤
│ ⑤ 逐品明细（保留，补持有期收益率、超额收益列）       │
│   可切「持仓中 / 已平仓」                          │
└─────────────────────────────────────────────────────┘
```

#### 新增后端需求

| 需求 | 位置 | 工作量 |
|---|---|---|
| 按时间区间算组合收益（统一口径，含理财） | `benchmark.go` 或新接口 | 中（需要把 pnl_daily 和 wealth_daily 对齐到同一区间） |
| 按区间算逐品收益（不是全持有期 XIRR，是区间内的收益率） | 新接口或 review.go 加参数 | 中（需要每品的每日市值序列或区间现金流） |
| 归因分解的 alpha 贡献 | 新接口 | 大（需要每日持仓明细 vs 目标配置快照） |

#### 风险

- 归因分解（选品 vs 配置）需要每日目标配置快照，项目里没有这个表，要么按"目标比例 × 每日总市值"推算，要么放弃归因分解，只做"逐品贡献排名"
- 多区间切换让后端计算量倍增，可能需要缓存

---

### 方案 C：叙事化 · 结论卡 + 可下钻（简化版，3-4 天，前端为主）

**核心思路**：不追求完整归因，只给用户"看完一句话就懂"的结论，然后按需展开。时间区间全局联动，但只联动"区间相关"的指标（基准对比、区间收益、逐品区间收益），年化这类"全持有期"指标保持不变。

#### 信息架构（从上到下）

```
┌─────────────────────────────────────────────────────┐
│ ① 结论卡（新增 · 首屏最上方，大字一句话）           │
│   「近 1 年：组合 +8.5%，跑赢沪深300 5.2pp」         │
│   副标题：年化 6.2% · 闲置现金 ¥12,345（每年少赚 ¥988）│
│   右侧：基准切换器 [沪深300 ▾]                      │
├─────────────────────────────────────────────────────┤
│ ② 区间切换条（轻量）                                │
│   [近 3 月] [近 6 月] [近 1 年] [全部]              │
│   只影响基准对比和"区间收益"指标（年化不变）         │
├─────────────────────────────────────────────────────┤
│ ③ 绩效归因 Top 榜（新增 · 比方案 B 的归因简单很多）  │
│   两个 Tab：「贡献最大」「拖累最大」                │
│   每行：品类色点 + 名称 + 区间收益金额 + 区间收益率  │
├─────────────────────────────────────────────────────┤
│ ④ 业绩表现卡（保留 · 补两列）                        │
│   补持有期收益率（并列年化）、超额收益列            │
│   每行可展开：流水明细                              │
├─────────────────────────────────────────────────────┤
│ ⑤ 闲置现金卡（恢复）                                │
│   从前端删掉的 idle 数据重新启用                    │
└─────────────────────────────────────────────────────┘
```

#### 解决的割裂问题（6 个全中）

| 割裂 | 方案 C 处理 |
|---|---|
| 数据源不一致 | 结论卡统一用"含理财"口径（改 benchmark.go 把理财算进去），不标注差异 |
| 时间窗口不联动 | 全局区间切换器；年化保持"全持有期"，基准对比和区间收益联动 |
| 年化 vs 持有期 | 结论卡和列表同时展示两个：大字年化 %，小字"持有 N 个月赚 M%" |
| 胜率模糊 | 删掉；结论卡说"跑赢基准 N pp"代替 |
| 后端白算数据 | 恢复闲置现金卡 + 展示目标年化差距 |
| 视觉层级 | 首屏结论卡用 hero 样式吸睛；基准对比降为次要（隐藏/折叠） |

#### 需要的数据

| 需求 | 做法 | 工作量 |
|---|---|---|
| **结论卡数据**（区间组合收益 + 跑赢指数） | `benchmark.go` 当前只算持仓，改成含理财；区间切换让后端按参数切片 | 小（1 天） |
| **逐品区间收益**（用于归因 Top 榜） | review.go 新增 `range` 参数；每品在区间内的累计盈亏 ÷ 区间期初市值 | 中（1-2 天） |
| **逐品持有期收益率** | 后端 review.go reviewItem 加 `holding_return = gain_cny / (gain_cny + mv_cny)` | 极小（半小时） |
| **闲置现金卡恢复** | 前端把 v6.2 删掉的 HTML/JS 加回来 | 极小 |

#### 风险

- 逐品区间收益需要每日市值序列，如果 pnl_daily 的 detail 字段里没有每品每日市值，就需要后端补算。当前 `pnl_daily.detail` 存的是 JSON，但不确定有没有每品市值。
- 归因 Top 榜的"区间收益"在区间切换时需要后端重算，4 个区间 = 4 倍计算量。
