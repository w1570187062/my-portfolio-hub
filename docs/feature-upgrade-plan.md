# 持仓侠 · 功能升级方案

## 现状速览

| 维度 | 当前能力 | 瓶颈 |
|------|---------|------|
| 持仓类别 | `stock` / `fund` 两类，market 二级分类（沪深/美股/港股/QDII/债券/股票/商品） | 没有 ETF/可转债/REITs/期权 等常见资产 |
| 理财 | `wealth` 表独立管理，支持净值/份额/每日快照 | 与持仓/现金的收益归属没有统一视图 |
| 现金 | 按"来源"分子账户（支持/钱包等），多币种 | 没有闲置现金统计、利率收益自动计算 |
| 负债 | 房贷/信用卡等，仅手动记录 | 没有还款预测、到期提醒 |
| 流水 | 持仓/理财操作自动记流水，收入支出计划手动 | 被动收入（分红/利息）没有统一归集视图 |
| 分析 | 盈亏日历 + 资产饼图 + 20日K线 + 持仓分析弹框 | 没有收益率归因、没有跨资产类别对比 |
| 规划 | 无 | 没有分红预测、没有被动收入覆盖率、没有目标追踪 |

---

## 升级方向（分 Phase）

### Phase 1：深化持仓分类 → 让分类更贴近真实资产

**目标**：让 category 能覆盖用户实际持有的常见资产类型，而不是"股票/基金"二选一。

#### 1.1 扩展 holdings.category 枚举

| 新 category | 说明 | market 典型值 | 行情源 |
|------------|------|--------------|--------|
| `stock` | 个股（保持） | 沪深/美股/港股/中概/ADR | yfinance/tushare |
| `fund` | 公募基金（保持） | A股基金/QDII/债券型/货币型 | 天天基金 |
| `etf` | ETF 场内基金 | 沪深 ETF/港股 ETF/美股 ETF | yfinance |
| `bond` | 债券/可转债 | 可转债/国债/信用债 | 手动或 akshare |
| `reits` | REITs 基础设施 | 公募 REITs/海外 REITs | 手动 |
| `derivative` | 衍生品 | 期权/期货/Warrant | yfinance |

前端筛选条自动适配——新增类别后 `CAT_MARKETS` 扩展映射即可，筛选 UI 无需改结构。

#### 1.2 持仓字段增强（可选）

| 字段 | 类型 | 说明 |
|------|------|------|
| `split_factor` | float | 拆股/分红除权累计因子（自动调整成本价） |
| `watch_price` | float | 自定义关注价（突破时提醒） |
| `notes` | text | 备注（买入理由、目标价、策略标签） |

#### 1.3 跨类别收益归因

当前 `/holdings/:id/analysis` 只看单只。新增**类别总览**：
- 每个 category 汇总：市值、总成本、总盈亏、收益率、贡献占比
- 在持仓页顶部切换"全部 → 按类别分组显示"

**后端改动**：`GET /api/holdings/analysis`（聚合接口），零前端改动。

### Phase 2：资产透视分析 → 财迹"底层持仓还原"方向

**目标**：当前项目有 `equity.items + wealth.products + cash + liability` 四块数据，各自独立展示。把它们放进统一坐标系。

#### 2.1 统一资产分布饼图（多维度）

当前资产页已有饼图，但只有"资产种类"一个维度。扩展为可切换：

| 维度 | 实现 |
|------|------|
| 资产类型（已有） | 持仓+理财+现金+负债 → 净资产 |
| 市场地域 | 沪深/港股/美股/其他 |
| 行业分布 | 从持仓 symbol 映射行业（需行情接口补充） |
| 货币 | CNY/HKD/USD 分开统计 |

**数据源**：`/api/asset/overview` 返回里已有 `region_assets`、`currency_assets`、`equity.items[].category/market`，前端聚合即可。

#### 2.2 收益热力图

把"盈亏日历"升级为**收益热力图**：
- 月视图：每格颜色 = 当日盈亏金额（已有）
- 叠加维度：hover 显示当日分解——持仓盈亏 + 理财盈亏 + 分红收入 + 利息收入
- 切换口径：金额 / 收益率（已有 calMetric 支持）

**后端改动**：`pnlHistory.detail` 里 `by_symbol` 已有，理财 `by_wealth` 已合并。需要额外合并分红流水 type=dividend。

#### 2.3 持仓 Top/Bottom 榜

持仓页新增切换 Tab：
- **按市值排序**（已有）
- **按收益率排序**
- **按盈亏金额排序**
- **按持仓天数排序**（套牢/长期持有）

**实现**：前端对 filteredHoldings 排序切换即可，零后端改动。

### Phase 3：被动收入归集 → 财迹"被动收入覆盖率"方向

**目标**：把分红、利息、理财收益这些"非主动交易收入"从流水里捞出来，展示覆盖生活支出的能力。

#### 3.1 被动收入统一视图

数据源：
- 持仓分红：`GET /api/holdings/:id/transactions` 过滤 type=dividend
- 理财收益：`/api/asset/wealth/:id/history` 每日累计收益
- 利息收入：现金账户余额 × 利率（需 cash 表新增 rate 字段，或利率手动配置）

聚合维度：
- 本月被动收入合计 + 构成饼图（分红/理财/利息 各占多少）
- 年被动收入走势（柱状图）
- **核心 KPI：被动收入覆盖月支出的月数 = 年被动收入 / (月支出 × 12)**

#### 3.2 分红日历（预测）

- 输入：历史分红交易（已录入）
- 预测算法：过去 3 年分红节奏外推（A股多为年度分红集中 6-8 月）
- 展示：日历格高亮预测分红月份 + 预计金额
- 数据源：纯历史记录，零外部 API

#### 3.3 月支出目标

- 手动输入月支出金额（或从收支计划汇总自动取）
- 实时展示：当前被动收入已覆盖 X/12 个月

**后端改动**：可选加 `users.monthly_expense` 字段存配置；或纯前端 localStorage 存。

### Phase 5：客户端 OCR 增强

#### 5.1 千分位自适应

中行等银行 App 用 `.` 当千分位（`70.019.95`），当前 `parse_number()` 只处理 `,`。

修复：解析时判断小数点数量——如果有多个 `.`，把所有 `.` 当千分位移除，然后尝试最后一个 `.` 作为小数点。

```python
def parse_number(s):
    # ... 现有逻辑 ...
    t = 去掉符号和括号
    dots = t.count('.')
    if dots >= 2:
        # 全部当千分位
        t = t.replace('.', '')
    elif dots == 1:
        # 保留一个小数点
        pass
    # ... 继续解析 ...
```

#### 5.2 多币种表头识别

银行/券商表头有「市值(元)」「市值(美元)」「净值(HKD)」等。SCHEMAS 关键词扩展：

```python
SCHEMAS["wealth"]["amount"] = [
    "金额", "本金", "市值", "持有金额", "持有市值(元)", "持有市值(美元)",
    "净值", "参考净值"
]
```

GUIDE 判页关键词同理扩展，靠 `keywords_any` 已有机制自动匹配。

## 核心设计原则

1. **优先用已有数据**：assetOverview 返回 region_assets/currency_assets，前端聚合即可，不新增接口
2. **category 扩展是增量的**：加新值不影响现有 stock/fund 持仓，前端 filter 自动生效
3. **客户端 OCR 修复与 Web 端解耦**：千分位修复只在 `client/ocr/table.py` 里改，不影响后端
4. **后端改动最小化**：Phase 4/5/2.3/2.1 纯前端就能完成，Phase 1.1 只需改枚举，Phase 3 可选加字段
