资产页结构重构 · 卡片海还是表格

真实数据 13 账户
结论

你的判断是对的，而且不是审美问题，是范式错配。资产页的核心任务是「对比」——比哪个账户钱多、比各地域占比、比负债占多少。业内共识很直接：对比用表格，浏览用卡片。你现在的 13 张账户卡，让每个余额停在不同的 x 坐标上，眼睛必须横跳才能比大小。

而且卡片框的门槛应该更高：一个数字不配拥有一个卡框，它只需要一个标题和值。现在顶部 6 张 KPI 卡各装一个数字、各占一个边框 + 阴影 + 圆角，正是最典型的「卡片泛滥」。

“Browsing tasks get cards, scanning tasks get lists, comparison tasks get tables. If users compare, tabulate; if they browse, card.” — UX Tigers《Cards: How a 3×5 Rectangle Conquered Screen Design》
01

四条被反复验证的判据

01密度塌陷
内边距、边框、留白通常吃掉半屏。表格一屏能放 20 行，卡片只能放 20 张中的 4 张。代价由滚动和放弃承担。
02层级消失
所有卡同尺寸时，琐碎与关键看起来一样重要。「12 张相同的卡宣称 12 个同等优先级，这通常是一个懒惰版式说的谎」。
03框比内容重
当框的重量超过了里面那一个事实，卡框就亏本了。十几个框，其实就是本该一张表里的十几行。
04装饰同质化
边框 + 阴影 + 背景色三层齐上就是噪音。三者留一个就足够划分区域。同一装饰重复 N 次，就从强调退化为纹理。
02

同类产品的做法

全是财务/资产类产品，且都面对「多个账户 + 多币种 + 需要对比」这同一道题。

Mercury企业银行
业内公认的银行 dashboard 设计基准。把「总仓位」放最上面最大字，下面是一行行账户，不是一堆卡——账户之间的关系可见，而不是藏在导航里。
聚合在前，拆解在后。总余额 → 账户行。
Stripe Dashboard支付
金融表格的教科书：右对齐等宽数字、行内 sparkline、下钻不丢上下文。色板中性，颜色只用来表示状态（成功/退款/失败），从不做装饰。
表格是主力面，图表只做摘要。
Fey组合跟踪
跟你的场景最接近。只给一个 hero 数字，其它指标不许抢；近乎单色，红绿只留给涨跌。
一个主数字，其余退后。
Wise Business多币种
唯一给「卡片」背书的案例——但注意它是单列列表式余额行，靠国旗等视觉 token 区分币种，不是 4 列网格。多币种需要的是识别 token，不是网格。
多维度用视觉标记，不用网格。

另注：行业共识的财务页纵向顺序是 ① 结论行（总余额/净仓位，最大字）② 正在发生的钱 ③ 现金流图 ④ 明细表（主力面）⑤ 异常告警。

2

指标条 + 全宽行卡

中间态 · 保留卡面

KPI 同样合并成指标条，账户仍是「卡」但改成每行一张全宽卡。保留卡面质感，余额也对齐了，但 13 张卡垂直堆叠后比表格多占约 30% 高度，且卡间距把「同组」的连续感打断了。

04

取舍

方案比大小密度分组表达改动量
0 · 现状✗ 余额错位 4 个 x 坐标低，20 个卡框靠地域 badge 逐卡标注—
1 · 指标条 + 表格✓ 同一 x 轴，含占比条高，一屏看完✓ 地域分组标题行带合计renderSources 重写 + 新 CSS
2 · 指标条 + 行卡✓ 同一 x 轴中，多占 30% 高△ 卡间距割裂分组中等，结构改动小
3 · 只合并 KPI✗ 账户仍错位中不变最小，半天
建议

走 1，但可以分两步落地降低风险：第一步先把顶部 7 张 KPI 卡合并成指标条（这一步单独做就能消掉一半的「卡片海」观感，且几乎无风险）；第二步再把 13 张账户卡换成地域分组表格，保留行内展开子账户的能力。
资产构成卡是图表模块，自包含、有资格拥有独立卡面——它保留为页面上唯一的卡。其余区域全部回到「线 + 表 + 字」。
